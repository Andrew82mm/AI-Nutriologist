# Бенчмарки качества пайплайна

Метрики для DA-нарратива проекта «из сырых чеков → чистые данные → польза». Это
не ML-лидерборд, а замер того, **сколько пайплайн делает бесплатными правилами**
(до платного LLM), **насколько корректно** он парсит чеки и **почему** доверяет
справочнику БЖУ больше, чем LLM.

## Запуск

```bash
python -m benchmarks.run_all            # пересобрать REPORT.md (#3 — из кэша)
python -m benchmarks.run_all --refresh  # заодно перезапросить LLM для #3

# по отдельности:
python -m benchmarks.bench_coverage        # #1
python -m benchmarks.bench_reconciliation  # #2
python -m benchmarks.bench_nutrition_llm   # #3 (нужен ключ LLM в .env)
```

Результат — [`REPORT.md`](REPORT.md) (витрина, коммитится).

## Три бенчмарка

| # | Что меряет | Эталон / с чем сравнивает | LLM |
|---|---|---|---|
| **1. Разделение труда** (`bench_coverage`) | доля работы без LLM (фасовка регуляркой, БЖУ из датасета); парсинг чеков — маршрутизация по формату (OFD.RU — правилами, остальное — LLM по задумке) | сам пайплайн (правила vs LLM) | нет |
| **2. Сходимость** (`bench_reconciliation`) | корректность парсинга: Σ позиций vs печатный ИТОГ (офлайн-чеки; онлайн-заказы вынесены — их ИТОГ включает сборку/доставку) | сам чек (самопроверяемая истина) | нет |
| **3. Ошибка БЖУ** (`bench_nutrition_llm`) | насколько LLM-оценка БЖУ отклоняется от эталона на **узнаваемых** продуктах (MAE/MAPE) | курируемая таблица (выверенные значения) | да (кэшируется) |

## Данные

- **Чеки** берутся из папки `чеки для парса/` в корне репозитория — это реальные
  выгрузки писем ОФД, **gitignored** (персональные данные), поэтому #1/#2 запускаются
  локально. Коммитится только итоговый `REPORT.md`.
- **Выборка #3** кэшируется в `results/nutrition_llm_vs_dataset.csv` (числа состава +
  оценки LLM, без персональных данных) — витрина рендерится офлайн без ключа.
- Выборки небольшие (корпус чеков + дев-БД) — числа иллюстративные, но на реальных данных.
