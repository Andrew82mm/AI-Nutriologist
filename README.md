# AI-Nutriologist

[![CI](https://github.com/Andrew82mm/AI-Nutriologist/actions/workflows/ci.yml/badge.svg)](https://github.com/Andrew82mm/AI-Nutriologist/actions/workflows/ci.yml)
![Python](https://img.shields.io/badge/python-3.12%20%7C%203.13-blue)

**Из сырых электронных чеков — в чистые данные, а из них — в учёт питания.**
AI-Nutriologist читает кассовые чеки из почты, приводит товары к единому виду, считает БЖУ и ведёт «холодильник»; съеденное вы вводите обычной фразой: «съел два яйца и кофе».

![Интерфейс AI-Nutriologist](docs/screenshot.png)

## Демо за 30 секунд

Без ключей, без сети и без LLM: синтетический чек проходит весь пайплайн.

```bash
python3 -m venv .venv && .venv/bin/pip install -e ".[api]"
.venv/bin/python demo/run_demo.py
```

## Как это работает

```
Письмо с чеком (IMAP) ─→ PDF ─→ текст ─→ парсер ─┬→ формат известен: правила (бесплатно)
                                                 └→ формат новый: LLM по JSON-схеме
                                                          │
                       дедупликация по ФД/ФПД ←───────────┘
                                │
                  нормализация товара + фасовка  ─→  «Холодильник» (журнал прихода/расхода)
                                                          │
«Съел X» ─→ разбор фразы ─→ БЖУ из справочника ─→ Дневник ─→ статистика, план, список покупок
```

## Инженерные решения

- **Правила первыми, LLM — только на промахе.** Известный формат чека (OFD.RU) разбирается детерминированным парсером; LLM подключается для незнакомых раскладок и новых товаров. Результат нормализации кэшируется, поэтому платный вызов случается один раз на товар.
- **Проверка парсинга самим чеком.** Сумма позиций сверяется с печатным ИТОГ. Онлайн-заказы вынесены отдельно: их итог включает сборку и доставку.
- **Идемпотентный импорт.** Повторное письмо с тем же чеком не создаёт дубль (уникальный ключ ФД + ФПД), а повторный приход в «холодильник» невозможен.
- **Инвентарь — журнал, а не счётчик.** Остаток — это сумма транзакций (чек, ручная правка, «съел», готовка), поэтому любое изменение можно проследить.
- **Фасовка из названия.** В чеке `quantity` — число упаковок, а не граммы: «Рис 5х80г» с `quantity=1` — это 400 г. Регулярки достают содержимое, LLM — только запасной вариант.
- **Честные цифры.** Источник БЖУ хранится у каждого продукта: справочник, ввод пользователя или оценка LLM. Оценка помечается в интерфейсе, а ручная правка запоминается.
- **Не привязан к провайдеру.** Anthropic или любой OpenAI-совместимый API (в том числе локальная модель) — выбор через `.env`. Без LLM приложение работает в офлайн-режиме.

## Качество пайплайна

Метрики считает пакет [`benchmarks/`](benchmarks/README.md), полный отчёт — [`benchmarks/REPORT.md`](benchmarks/REPORT.md). Корпус — реальные чеки автора (в репозиторий не входят), поэтому выборки небольшие, а цифры иллюстративные.

| Метрика | Результат |
|---|---|
| Фасовка извлечена регулярками, без LLM | 47 из 62 позиций (76%) |
| БЖУ взято из справочника, без LLM | 19 из 27 продуктов (70%) |
| Чеки, разобранные правилами (остальные — через LLM) | 4 из 10 |
| Сумма позиций = ИТОГ чека (офлайн-чек) | 1 из 1, расхождение 0.00 ₽ |
| Ошибка LLM-оценки калорий против справочника (MAE) | 23.5 ккал на 100 г |

Главный вывод третьего бенчмарка: LLM неплохо оценивает узнаваемые продукты, но путается в неоднозначных названиях («рис» — сухой или варёный), поэтому справочник стоит в каскаде раньше модели.

Реальные LLM и IMAP в тестах заменены фейками.

## Что умеет приложение

- **Дневник** — приёмы пищи за день, БЖУ и калории относительно цели.
- **Статистика** — тренд калорий, достижение цели, баланс БЖУ, траты по категориям из чеков.
- **Холодильник** — что и сколько есть дома; правки вручную.
- **План** — меню на день под цели, список покупок за вычетом остатков, рецепты из имеющихся продуктов.
- **Профиль** — цели (расчёт по Миффлину-Сан Жеору), ограничения, параметры тела.
- **Чат** — «съел…», «купил…», «приготовил…», «отчёт за день», «что приготовить?».

## Запуск приложения

Нужен Python 3.12+ и Node.js (для веб-интерфейса).

```bash
# 1. Бэкенд
python3 -m venv .venv
.venv/bin/pip install -e ".[api]"
.venv/bin/python -m nutriologist.api        # http://127.0.0.1:8000

# 2. Фронтенд (в отдельном терминале)
cd web/app
npm install
npm run dev                                  # http://localhost:5173
```

Чтобы включить LLM-функции (незнакомые чеки, оценка БЖУ, разбор сложных фраз, планировщик), скопируйте `.env.example` в `.env` и укажите провайдера и ключ. Для автоматического получения чеков заполните там же `MAIL_*` и запустите `python -m nutriologist.mail.cli --watch`. Разбор PDF требует `pdftotext` (пакет poppler).
